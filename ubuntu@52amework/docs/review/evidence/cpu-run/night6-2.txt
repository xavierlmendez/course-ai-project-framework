completion_tokens 372, total 2422. The reasoning string is byte-for-byte the same in all
four runs (same seed, same prompt).

CONCLUSION: adding "think": false to a /v1/chat/completions body changes NOTHING. Ollama
0.33.3's OpenAI-compatibility layer discards the field before it reaches the chat template.
Proof by identity: had it been honoured, the qwen3 template would have appended " /no_think"
to the last user message and prefilled "<think>\n\n</think>\n\n" on the assistant turn,
which cannot produce an identical 1644-char reasoning block.

Neither is stream/non-stream the problem: both shapes fail identically. The model simply
plans inside the think block and then emits EOS.

The `think` parameter DOES work on the native /api/chat endpoint (that is where the earlier
5/5 tool-call result came from). OpenCode uses /v1 exclusively, so that lever is unavailable
to it. See night6-3.txt and night6-4.txt.
